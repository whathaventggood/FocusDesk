# FocusDesk：允许适度功能调整后的体验路线

日期：2026-11-09。状态：功能已在 macOS 3.2.0（构建 9）开发候选中实现；以下保留设计与验收依据。实际执行结果及未完成的环境依赖检查见 [3.2 验收报告](VALIDATION-3.2.md)。基于现有代码、上一轮体验路线和原始的多学习项目辨认场景。

## 目标与范围

让人更容易回答四个问题：现在开始学什么、某一天学了什么、已经结束的项目怎样保留、记录需要修正时怎样安心操作。

沿用本地保存、低打扰、一次一个计时的定位。首版使用现有窗口，优先少量高收益改动；后续按试用结果扩大范围。以下用户收益为设计判断，需通过实际使用验证。

## 当前路径的主要机会

- 每日趋势能逐块悬停，但很多小柱块仍需要精确定位；明细随光标离开而消失。
- 开始一次计时需要选择项目与参数，已有参数主要作为页面状态保存；窗口上还长期展示完整的新建表单。
- 图例和列表随着项目数量持续增长，当前项目选择缺少查找能力。
- 项目只有删除入口，删除会连同全部记录移除；完成的课程仍需保留在日常列表中才能保存历史。
- 计时记录主要是一列项目名、开始时间和时长，回看某一天的具体内容需要自己寻找。
- “专注记录”实际展示计划任务完成率，与“事项计时”中的学习时长是两套含义，应明确命名和统计范围。

## 推荐首版：四项功能调整

| 调整 | 主要收益 | 预计工作量 | 数据改动风险 |
| --- | --- | --- | --- |
| 点击日期，固定查看当天明细 | 小柱块也能轻松查清项目与时长 | 中 | 低，主要为只读交互 |
| 项目查找与“只看此项目” | 项目增多后仍能迅速定位 | 小至中 | 低，区分查询与统计筛选 |
| 最近项目与记忆计时参数 | 减少每天重复选择和设置 | 小至中 | 低，主要是本地偏好 |
| 项目归档与恢复 | 日常列表更短，历史记录保留 | 中 | 中，需要版本化迁移与统计回归 |

### 1. 日期明细：悬停预览，点击后稳定阅读

操作示例：进入统计 → 点击“11 月 8 日”的柱子或日期 → 在图下方看到该日项目清单、完整名称和时长 → 需要时查看对应记录。

设计规则：

- 悬停继续识别单个柱块；点击选择整天，固定明细直到更换日期或关闭。两个状态独立，光标移动不会覆盖已经固定的阅读内容。
- 明细按时长排序，让几秒钟的小项目也能通过文字找到；保留图例、柱块与明细一致的固定编号。
- 明确显示“当前筛选项目合计”及筛选范围。点击日期只改变查看对象，不修改记录，也不自动改变项目筛选。
- 普通窗口把明细放在图下方；宽窗口可以放在图右侧，避免遮挡柱图。第一版不增加独立弹窗。
- 日期切换、项目筛选、空记录和窗口缩放后重新核对明细；范围变化导致日期不再可见时清理日期选择。
- 跨日记录按该日本地日期内的有效片段计算；从日明细打开整次记录编辑时，清楚说明编辑作用于整次记录。
- 键盘与辅助技术应能进入同样的明细，获得项目、日期与时长，而不是仅获得颜色说明。

验收：任意一天的完整明细一次点击可达；存在极小柱块时仍可查找；日明细使用与图表相同的筛选和时间口径。

### 2. 项目查找：减少翻找，并保持筛选含义清楚

操作示例：打开项目选择 → 输入“SQL” → 选择项目；在统计中使用明确的“只看此项目”动作聚焦其趋势，再返回全部。

设计规则：

- 查找支持名称匹配、清除和键盘选择；名称及编号一起展示。
- 输入查询只缩小候选项目列表；显式选择或勾选后才改变统计数据。
- 图表附近持续显示当前项目筛选，提供清楚的返回全部入口；“查看一天”“高亮项目”和“筛选统计”分别表达。
- 新建同名项目时优先提示已有项目；遇到已归档同名项目，提供恢复已有项目的明确选择，不静默合并。
- 逐步记住日期范围、排序和项目筛选；恢复偏好时移除已经删除的标识。

验收：50 个项目时可以通过输入与一次明确选择完成定位；查找文字变化不偷偷改变累计数值；退出再打开后筛选范围清楚可知。

### 3. 最近项目：进入页面后直接开始

操作示例：“SQL · 正计时 · 开始”或“阅读 · 25 分钟 · 开始”。参数已经可见，点击清楚标注的开始按钮后才启动。

设计规则：

- 先展示最近使用的 3 个有效项目，记住每个项目上次的计时方式和倒计时时长。
- 完整的新建项目表单由一个“新建项目”入口展开，把首屏留给当前计时与最近项目。
- 打开应用、恢复窗口、恢复偏好和唤醒均不自动开始计时；睡眠后继续仍由用户决定。
- 无有效最近项目时展示清楚的首次使用入口；项目删除或归档后清理无效快捷项。
- 有计时正在运行时，当前状态优先；首版沿用单计时约束，避免快捷开始隐含结束正在运行的记录。
- 保存反馈就在执行操作附近；未提交的输入不被较早请求清空。

验收：进入计时页后，最近项目的一次明确点击即可开始；项目和参数在点击前可见；重启不自动计时。

### 4. 项目归档：结束一门课程后保留历史

操作示例：课程结束 → 归档项目 → 从默认开始列表和最近项目中移出 → 历史累计和记录仍然保留 → 日后从归档列表恢复。

设计规则：

- 归档只改变日常开始入口，保留项目标识、固定编号、颜色、原始片段和累计。
- 历史统计包含归档项目；统计和查找中可以找到它们，不能因为项目归档而让旧合计静默减少。
- 当前正在计时的项目先结束或显式切换后再归档；第一版避免归档操作同时隐含结束计时。
- 恢复后沿用原项目身份；同名归档项目通过明确恢复动作继续累计。
- 普通停用入口优先使用归档；永久删除放到清楚的项目管理位置，并保留不可恢复的确认说明。
- 为旧文件提供默认未归档状态，保留迁移备份，验证失败后不会只迁移一半。新格式版本与旧版本写入兼容性需明确验证。

验收：归档、重启、筛选和恢复后，历史时长、原始片段与固定编号保持一致。

## 后续候选：试用后逐项加入

### 记录按天查看，加一条可选的本次内容

项目可以保持课程或主题粒度，例如“SQL”；记录中可选填写“窗口函数练习”。这能帮助回忆具体内容，也为减少过细项目提供选择。

- 备注放在记录编辑和结束后的轻量入口中，默认可以留空，不强制弹出填写表单。
- 按天组织记录，并提供项目和日期定位。列表组织日期与每日时长归属分别处理，跨日片段仍按统计规则拆分。
- 一条记录对应一个可选备注字段，旧记录默认空；不引入多层标签、目录和必填学习报告。
- 点击日明细的记录入口，传递日期和项目上下文，返回时保留原查看位置。

### 一步切换学习项目

适合学习过程中频繁从 SQL 切到网络课程的情况，但修改计时状态的风险高于只读交互，安排在基础版本稳定以后。

- 用户明确选择目标项目后，在同一次提交中按一个时间点结束 A 并开始 B。
- 任意一步失败均保留完整原状态，避免 A 已结束但 B 没开始。
- 处理暂停中的 A、已到时的倒计时、已删除的 B、保存等待中睡眠、快速双击和其他窗口更新。
- 保持同时最多一个计时，不把项目搜索、归档或普通点击变成隐式切换。

### 对具体修改提供可预期的撤销

先支持改名、归档和时长修正等边界清楚的操作，显示“撤销归档”“撤销时长修改”等明确名称。

- 撤销只恢复对应字段或记录，不能回滚整个文件并覆盖之后新增的学习记录。
- 保留文本输入控件原有的撤销行为；应用操作撤销的菜单和快捷键与文本编辑正确分工。
- 用户需要知道哪次修改会被恢复；恢复完成后能看到结果。存在外部冲突时明确说明，避免覆盖他人的新修改。
- “恢复原时长”继续表示回到原始计时；“撤销本次修改”表示回到上一次值，两者含义不同。

## 页面结构的渐进调整

首版沿用现有窗口，先收起低频新建表单、增加日期明细与查找，不一次替换全部导航。

如果试用仍频繁在长页面来回滚动，再在事项计时窗口内整理“计时 / 学习统计 / 学习记录”三个区域，保留一条当前计时状态。日期明细跳转记录时携带上下文，不要求用户重新筛选。

现有“专注记录”页面展示的是计划任务完成率，建议使用更明确的“计划回顾”名称；学习时长与计划完成率分别说明，避免把投入时间当作学习效果或任务完成证明。

## 实施路线与停止条件

| 阶段 | 功能范围 | 支撑工作 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0：真实基线 | 暂不扩大功能 | 补齐可用的界面测试环境，基于生产后台流程验证中文输入、点击和保存 | 有可复现的典型任务结果，跳过项清楚列出 |
| 1：看得懂 | 日期固定明细、项目查找、只看此项目 | 分开日期选择与项目筛选，优化高亮层，验证跨日口径 | 50 项目可定位，极小柱块可通过明细查找，范围无歧义 |
| 2：用得快且列表可控 | 最近项目、每项目参数记忆、归档恢复 | 偏好清理、旧数据迁移、首屏布局调整 | 最近项目一次开始，归档不改变历史，重启不自动计时 |
| 3：回顾与操作可逆 | 按天记录、可选备注、限定范围的撤销 | 记录上下文跳转、操作级恢复和冲突检查 | 无必填负担，撤销不影响后续记录，跨日编辑含义明确 |
| 4：按试用触发 | 快速切换计时、窗口内分区 | 原子切换、退出/睡眠并发和全路径回归 | 连续使用后证明有需求，基础流程保持简单且稳定 |

前三个新增交互的试用目标应以典型任务完成情况为准，而不是功能数量：查清指定日期、从大量项目中找到目标、开始最近项目、保留已结束课程的历史。

性能与可靠性沿用前一份路线：后台首次统计、保存成本、可见性相关刷新、强制退出恢复和同一安装包验收。前次测得的约 125 ms/1.28 s 为特定数据下一万/十万记录只改名保存的中位数，不是整个产品的响应时间或 P95；新增功能不能把这些成本重新放回界面线程。

## 推荐决策

先交付阶段 1，再交付阶段 2，形成四项首版调整。阶段 3、4 保持候选，依据实际使用再决定。每轮有独立可用版本，保留旧记录，检查明确的数据含义与恢复路径。

## 依据与来源

- 当前 `ActivityTimersView` 将设置、统计和记录放在同一滚动页面；计时参数与统计偏好主要由页面状态持有。`ActivityTimerDocument` 当前支持删除项目及记录，尚无归档状态或记录备注。
- 当前 `HistoryView` 回顾计划完成情况，学习计时记录位于事项计时窗口，两者具有不同统计定义。
- [Apple：图表](https://developer.apple.com/design/human-interface-guidelines/charts)：清楚提供图表含义、数据上下文和完整可访问性。日期明细为结合当前场景提出的设计方案。
- [Apple：搜索](https://developer.apple.com/design/human-interface-guidelines/searching)：明确当前搜索范围，帮助使用者理解搜索结果。
- [Apple：撤销和重做](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo)：使撤销结果可预期，明确展示恢复的操作与结果。
