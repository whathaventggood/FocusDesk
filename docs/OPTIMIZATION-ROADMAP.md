# FocusDesk 后续优化路线

研究日期：2026-11-09。基于当前未提交版本、上一轮验收报告、现有截图和本轮独立保存补测。延续已有范围：改善现有体验、性能和可靠性；每阶段交付可使用、可复验的版本。

## 结论与现状

现有固定编号、逐块悬停、统计索引、后台计时保存和睡眠恢复已有基础回归。下一阶段的主要价值依次是：补齐真实操作证据、稳定读图与操作反馈、降低首次处理和保存成本、减少常驻消耗，并让后续修改更可控。

原研究阶段为代码复查与补测。随后 macOS 3.2.0 候选已落实新功能、后台统计准备、较低频率的空闲检查、紧凑存储与版本化安装包；以下保留原始测量与路线，最新验证见 [3.2 验收报告](VALIDATION-3.2.md)。

| 已有证据 | 对下一轮的含义 |
| --- | --- |
| 上轮 540 项原生回归通过，但真实鼠标/输入及完整 XCTest 未完成 | 自动检查数目不能替代输入焦点、中文输入法和真实鼠标的验收 |
| 窗口回归大量采用同步兼容路径，后台保存另有专项 | 下一轮需要让真实窗口操作走生产后台保存路径，覆盖组合行为 |
| 缓存统计读取约 0.002 ms；运行片段增量统计约 0.005 ms | 继续微调这些计算的用户收益较小 |
| 一万/十万条记录的首次统计快照约 12/81 ms | 统计索引仍由主界面调用链同步建立，首次打开和大规模变更值得优化 |
| 命中索引处理 5,000 次查询约 12 ms | 命中计算已有改善；悬停后界面的实际重绘仍需单独测量 |
| 本轮只改名保存：一千/一万/十万条记录中位数约 15/125/1,278 ms | 后台保存仍有可感知等待，全量文件处理是后续优化方向 |

本轮保存探针使用 100 个项目、每条记录一个已完成片段、独立临时目录和优化编译；每种规模测量 5 次。十万条记录文件约 32.3 MB。它测量读取、修改、校验、编码和原子保存的合计耗时，不是界面延迟或 P95，也不应与不同数据、不同目录的历史测量直接比较。原始结果见 `docs/benchmarks/2026-11-09-save-probe.json`。

## 第一阶段：建立真实使用基线

优先级 P0；工作量中等。完整 Xcode 和可用界面测试环境是端到端检查的前置条件。

交付内容：

- 在隔离的目录与偏好中启动实际应用，保留生产后台读写、时钟和窗口行为；隔离数据不应同时改变被测的保存实现。
- 测量从打开窗口到首屏可用、点击到反馈、反馈到持久化完成、鼠标移动到正确提示、滚动帧耗时。
- 加入中文输入法候选、组合输入、光标位置、长文本粘贴、改名时实时排序越位、快速连击、滚动中悬停和窗口缩放的测试。
- 使用 5/20/50 项目的日常场景与 100 项目的压力场景；记录规模分别覆盖一千、一万和十万条。记录平均值、P95、最大值与机器条件。
- 在关键阶段增加开发用计时标记，分清后台计算、界面发布、排版、绘制和磁盘提交的耗时。

通过标准：真实鼠标和输入用例有清楚结果；跳过项单列；缺少界面环境时保持为待验证。建立同机可重现基线后再设性能回归门槛。

## 第二阶段：读图稳定与操作反馈

优先级 P1；工作量小至中等，适合逐项交付。

1. **分离悬停装饰层。** 当前悬停覆盖层仍遍历全部柱块，逐个判断是否需要高亮。把静态边框和编号与当前高亮分开，让一次切块主要更新一个高亮框和一个提示框；保留细柱块的命中容错和真实比例。先用第一阶段的实际绘制测量确认收益。
2. **稳定提示框。** 约束长名称的宽度与换行，减少跨相邻柱块时不必要的位置跳动；靠边、缩放和滚动后仍显示正确详情。提示不依赖额外等待来掩盖更新成本，也不放大数据柱块来改善命中。
3. **优化多项目图例。** 以 20/50 项目测试文字与间距，评估按内容宽度排布，减轻统一大单元格的空白。保留固定编号、完整名称提示和现有筛选行为。100 个长名称仍需要滚动，不能仅靠增加颜色解决密度问题。
4. **就地解释保存状态。** 在正在执行的操作附近表达“保存中/保存失败”，让暂停期间冻结的时间与状态说明一致。提交后新输入不被旧请求清空，失败保留草稿。
5. **稳定阅读位置。** 延续改名时固定行顺序；实时排序、筛选和外部更新时验证滚动锚点，避免正在阅读的行突然离开视野。
6. **核对可访问性。** 检查现有按钮的键盘顺序、选中状态、图表播报和系统提高对比度；确保辅助技术获取的项目、日期、时长与悬停内容一致。

通过标准：真实切块提示无串项，细块与间隙边界正确；20/50 项目、长中文/英文名称、深浅主题和窄窗口通过截图与实际操作验收；中文输入与焦点用例全部通过。

## 第三阶段：首次可用速度与保存成本

优先级 P1；工作量中等，依赖第一阶段的测量。

### 先处理可定位的重复工作

- 把首次历史索引和大规模变更后的统计准备移到后台，使用只读快照向界面发布；当前运行片段继续增量计算。
- 快照发布校验数据版本、日期与时区；旧请求的结果不能盖过新操作。跨日、时区切换和时钟回拨沿用独立算法对照。
- 在保存成功后评估安全复用本次提交结果，减少下一次操作重新解析自己刚写入文件的成本。缓存必须能证明文件属于本次提交，保留同大小外部改写、时间恢复、替换和删除重建的检查。
- 分别测量校验、编码、文件大小和原子替换，评估减少 JSON 空白和重复校验的收益。保留文件格式兼容性与损坏保护。
- 对计划和完成历史单独建立长期数据基线：这一部分当前仍在界面线程读写。只有测得影响后再按同样方式迁移，避免把计时文件的结果套用到所有存储。

### 用目标约束改动

建议首轮目标，尚非已达结果：

- 常用规模下，点击后的视觉反馈 P95 低于 100 ms；持续拖动、悬停等路径争取把应用自身主线程工作压到约 5 ms 内。
- 一万条记录的普通保存完成 P95 争取低于 200 ms；日常小数据不明显退化。
- 十万条压力数据的首次索引不在界面线程形成长任务，加载期间窗口仍能输入、滚动和关闭。

P95 需用更多重复样本及多台目标设备建立，不能由本轮 5 次中位数推导。Apple 的响应性建议也区分离散操作与连续运动，具体预算需结合目标设备测量。

### 存储迁移的触发条件

先完成上述轻量改动。若真实常用数据或保存队列仍持续超标，再评估事务化存储。迁移必须包含旧文件备份、版本识别、重复迁移保护、失败恢复、原始计时片段保留，以及新旧结果逐项对照。避免把项目与记录简单拆成两个独立覆盖的文件，造成一致性问题。

## 第四阶段：常驻消耗、状态与交付收口

优先级 P2；工作量中等，可在前述阶段逐步推进。

- **按需刷新。** 当前每秒时钟还会安排文件检查。把显示用秒更新、外部文件变更检查、午夜任务切换和倒计时截止处理分别安排。窗口隐藏时减少无意义绘制；后台倒计时到点、睡眠与唤醒仍必须准确处理。
- **测量能耗。** 比较空闲、只显示方块、展开详情、隐藏窗口和特效运行五种状态下的 CPU、唤醒次数与内存，连续运行并反复开关窗口检查增长趋势。节省幅度以同机测量为准。
- **统一状态转换。** 逐步收拢加载、保存、睡眠暂停、退出等待和过期请求处理；让测试尽量调用与生产相同的异步操作入口，减少同步/异步两套流程偏离。
- **做中断恢复测试。** 除现有模拟保存失败外，增加在写入、原子替换、睡眠恢复记录合并期间强制退出进程的测试，核对重启后的记录完整性、无重复累计和明确错误。
- **绑定交付物。** 安装包名称、现有版本说明、构建号、校验值和验收报告对应同一产物，减少新旧包混淆；性能回归采用专用测量或稳健基线，避免共享 CI 机器的噪声阻断无关修改。

通过标准：后台减少工作不影响计时正确性；进程中断与恢复用例通过；反复开关和长时间运行无持续资源增长；待交付安装包完成实际操作验收。

## 范围与取舍

- 当前最低支持 macOS 13。继续通过局部依赖拆分改善刷新范围；全面切换到要求 macOS 14 的新观察方式，应作为另行评估的兼容性决定。
- 当前数据规模尚不足以直接决定全面重写存储或图表。先取得真实操作和组件绘制数据，再选择改动。
- 继续维护现有业务范围。本路线不引入账号、云同步、学习推荐或新的统计入口。
- Windows 单列后续计划：当前实现与 macOS 存在差异，包括同步保存和窗口整页重建。若继续双端交付，应分别建立行为与性能验收；macOS 结果不能直接作为 Windows 结论。

## 执行顺序

真实操作基线 → 悬停与保存反馈 → 后台快照及保存成本 → 常驻能耗和中断恢复 → 同一安装包验收。每阶段保留前一阶段的测试，通过后再继续；事务化存储按测量触发。
